@AGENTS.md

## What this is

Frontend for the IGI/IHMS **Claims & Pre-Authorization portal** — a two-role (CUSTOMER / OFFICER) workflow app over a single `Request` resource with an immutable audit trail.

[SPEC.md](SPEC.md) is the **shared contract with the backend repo** (an identical copy lives there). It owns the state machine, enums, data model, API surface, error codes, and seed credentials. Read it before writing any domain code, and never change enum values, status names, or DTO field names here without changing it in both repos.

The backend is a separate service reached over `NEXT_PUBLIC_API_URL` (`.env.local`, e.g. `http://localhost:4000/api/v1`). There are no route handlers or server-side data access in this repo — all data comes from that API.

## Version reality check

The stack is newer than most training data. Concretely, in this repo:

- **Next.js 16.3 / React 19.2, App Router.** Turbopack is the default for `dev` *and* `build` — no `--turbopack` flag.
- **`params`, `searchParams`, `cookies()`, `headers()` are async only.** Synchronous access was removed in 16.
- **Route-typed prop globals** are generated by `next typegen` and used instead of hand-written prop types: `PageProps<'/requests/[id]'>`, `LayoutProps<'/'>`, `RouteContext<'/...'>`. See [src/app/layout.tsx](src/app/layout.tsx) for the existing usage. Awaiting `props.params` is required.
- **`middleware.ts` is deprecated → `proxy.ts`**, exporting a function named `proxy`. It runs on the Node runtime only (no edge). Config flags renamed accordingly (`skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`). Note that CLAUDE-frontend.md still says `middleware.ts`; the file to create is `src/proxy.ts`.
- **shadcn/ui here is built on `@base-ui/react`, not Radix.** Every primitive in [src/components/ui/](src/components/ui/) imports from `@base-ui/react/*`. Do not paste Radix-era shadcn snippets, and do not add `@radix-ui/*` packages.
- **Icons are Phosphor** (`iconLibrary: "phosphor"` in `components.json`); the `ui/` primitives import from `@phosphor-icons/react`. `lucide-react` is also installed, but prefer Phosphor for consistency.
- **Tailwind v4, CSS-first.** There is no `tailwind.config.*` — theme tokens, the `dark` variant, and base layer all live in [src/app/globals.css](src/app/globals.css) via `@theme inline` / `@custom-variant`. Add design tokens there as CSS variables, not in a JS config.

Verify anything version-sensitive against `node_modules/next/dist/docs/` (e.g. `01-app/02-guides/upgrading/version-16.md`) rather than from memory.

## Architecture rules that matter

These come from CLAUDE-frontend.md and are the ones worth not rediscovering:

1. **Status logic is data, not JSX conditionals.** One `STATUS_META` map plus `customerActions(status)` / `officerActions(status, isAssignee)` helpers in `lib/constants/statuses.ts`; components read from them. The transition table in SPEC.md §3 is the source of truth, and the frontend copy is UX only — the backend enforces it.
2. **One `createApi`.** `store/api/baseApi.ts` owns `fetchBaseQuery`, the 401-refresh wrapper (mutex-serialised so parallel 401s fire one refresh), and the whole `tagTypes` list. Feature APIs use `baseApi.injectEndpoints()`.
3. **Unwrap the envelope at the API layer.** `transformResponse` strips `{ success, data, meta }`; `transformErrorResponse` normalises to `{ code, message }`. Components never see the envelope.
4. **Access token in Redux memory only** — never localStorage, never redux-persist. The refresh token is an httpOnly cookie; `credentials: 'include'` carries it. Session restore on reload is a `getMe` call, not persistence.
5. **Every request mutation invalidates `Request`, `RequestList`, `AuditLog` (for that id), and `Stats`.** A status change that leaves the timeline stale reads as a bug.
6. **URL search params are the source of truth for list filters**; derive the RTK Query arg from them so the officer queue is refresh-safe and shareable.
7. **Zod schemas mirror the backend DTOs exactly**, including `serviceProvider` required when `requestType === 'HMO_PRE_AUTHORIZATION'` (`.superRefine`). Drift turns field errors into server errors.
8. **Comment-required and destructive actions go through a dialog** with a required textarea (mirrors the backend's `COMMENT_REQUIRED` for `NEEDS_ADDITIONAL_INFO` and `DENIED`).
9. **Uploads:** send `FormData` as the mutation body and never set `Content-Type` yourself. Client-side checks mirror the server: PDF/JPEG/PNG, 5 MB, 5 files.
10. **`proxy.ts` gates on a session *hint* cookie, never the refresh cookie.** CLAUDE-frontend.md says the middleware reads the refresh cookie for presence; that is impossible with this deployment. The API sets `refreshToken` with `Path=/api/v1/auth; HttpOnly; Secure; SameSite=None` on **its own domain**, and cookies are domain-scoped — the Next server is a different origin and can never read it. Gating on it bounces every signed-in user back to `/login`. [src/lib/session-hint.ts](src/lib/session-hint.ts) writes a non-sensitive, JS-visible `igi_session` cookie on login/refresh and clears it on logout or a rejected session; `proxy.ts` reads that. It carries no identity, so role separation still belongs in the route group layouts.

## Conventions

- Import via the `@/*` alias (→ `src/*`). shadcn aliases: `@/components/ui`, `@/lib/utils`, `@/lib`, `@/hooks`.
- Compose class names with `cn()` from [src/lib/utils.ts](src/lib/utils.ts).
- Add primitives with `npx shadcn@latest add <component>` so `components.json` (`style: base-lyra`, `baseColor: neutral`) stays authoritative; don't hand-write files into `ui/`.
- Server Components by default; `"use client"` only where interactivity or hooks require it (the store provider, forms, most `ui/` primitives).
- **Geist Sans is the default face.** The base layer applies `font-sans` on `html`, and `--font-heading` maps to it too, so the wide `font-heading` usage stays sans. Geist Mono remains wired to `--font-mono`; use `font-mono` deliberately for IDs, amounts, and other tabular/code-ish text.
